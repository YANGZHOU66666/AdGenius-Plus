# SFT 与 OPD 蒸馏实验方案

本文描述训练与评测方案的设计：用同一个教师，分别通过 SFT 和在策略蒸馏（OPD）训练 0.8B 学生，再比较两者的效果。

状态截至 **2026-11-24**：学习率已选定（OPD `beta=0.5`、2e-6；SFT 5e-6）；正式训练已完成，两种方法 1k/2k/4k/8k 的 test 和 dev 输出以及参照系统（未训练学生、397B 老师）的 test 输出已入库（[训练报告](../results/training/formal_v1_report.md)）；test 评测尚未开始。设计依据、试点结果和工程备忘见[训练实验杂记](training_notes.md)。

## 1. 研究问题

固定教师和商品 prompt，在短文本广告生成任务上，比较 SFT 和 OPD 两种方法：哪种能把更多广告质量传给 0.8B 学生？

**假设**：OPD 能在同一个商品上反复采样，并由教师逐 token 给出反馈，因此在商品数量少时可能更省数据；商品数量增加后，SFT 会逐渐追上。数据规模这条轴就是用来检验这一点的。

## 2. 固定设置

| 项目 | 设置 |
|---|---|
| 学生 | `Qwen/Qwen3.5-0.8B`，以纯文本模型加载，全参训练 |
| 教师 | Qwen3.5-397B-A17B，关闭思考，temperature 1.0，top_p 1.0 |
| 生成 prompt | `data/eval/gold/manifest.json` 中冻结的系统提示 |
| chat template | `enable_thinking=False`，训练与推理一致 |

## 3. 数据

### 3.1 数据集分工

| 数据集 | 数量 | 用途 |
|---|---|---|
| gold | 100 | 只用于评委校准和人工标注，不参与选模型 |
| dev（新建） | 200 | 选学习率、监控训练 |
| test | 1,000 | 只在最后评测一次，报告正式结果 |
| train（新建） | 8,000 | 训练 |

dev 和 train 都从训练池抽取，按 `group_id` 去重。四个数据集互不重叠，由测试自动检查。

### 3.2 训练集

1. **过滤**：去掉没有标题的商品，以及卖点和描述都缺失的商品；去掉商品信息过长的；每个 `group_id` 只保留一条；排除 dev 中的商品。
2. **固定顺序**：用固定种子抽取 8,000 个商品并打乱，每条记录带 `rank`（0–7999），写入 `data/train/v1/`。
3. **嵌套规模**：前 1k、2k、4k、8k 个商品分别对应四个数据规模，每一档都包含前一档。
4. **种子**：商品集合固定不变。每个种子只打乱 `[0,1k)`、`[1k,2k)`、`[2k,4k)`、`[4k,8k)` 这四段各自内部的顺序，段与段之间的先后不变。正式训练两种方法都只用种子 20261123。

### 3.3 教师信号

- **SFT**：教师（阿里云百炼）为每个商品生成 1 条广告，生成一次后冻结，所有组别和种子共用。
- **OPD**：教师（Tinker）实时给学生的采样逐 token 打分，不需要预先生成广告。
- 正式训练前，检查两个部署是否等价：在同一批 token 上逐个比较两边给出的 logprob。

## 4. 两种方法

| | SFT | OPD |
|---|---|---|
| 训练信号 | 教师写的广告（离线模仿） | 教师对学生自己采样的逐 token 打分（反向 KL） |
| 实现 | TRL `SFTTrainer`，只对广告部分计算 loss | TRL `ServerDistillationTrainer`，教师通过兼容 vLLM 接口的代理访问 |
| 每个 prompt | 1 条教师广告 | 学生采样 4 次 |
| 损失 | 交叉熵 | `beta=1`（只用采样 token 的分数），或 `beta=0.5`（另外引入教师首选的 token）；**选定 `beta=0.5`**，见 §5 |

## 5. 训练配方

| 项目 | SFT | OPD |
|---|---|---|
| 精度与优化器 | fp32 主权重，bf16 混合精度，AdamW | 同左 |
| 学习率候选（只在 1k 上选） | 5e-6、1e-5、2e-5 | 5e-7、1e-6、2e-6 |
| 调度 | 固定步数 warmup，之后学习率恒定 | 同左 |
| 每步数据 | 40 条 | 40 个 prompt × 4 次采样（这样 1k/2k/4k/8k 都落在整步上） |
| 种子数 | 1 | 1 |

**学习率选择**：两种方法使用同一套规则，评委与 test 相同，都用 DeepSeek。

1. 每个候选学习率都用训练集的前 1k 个商品训练一次，单种子。
2. 训练中 loss 发散或出现 NaN 的候选直接排除。
3. 同一方法剩下的候选两两对比：每对在 200 个 dev 商品上按 AB、BA 两个顺序各评一次。3 个候选共 3 对，需要 1,200 次评委调用。
4. 选赢得最多的候选。如果它对第二名的胜率在按商品 bootstrap 的区间中包含 50%，就视为打平，在这两个候选中选较小的学习率。
5. 选定之后，用同一个学习率从头训练到 8k（选学习率时的 1k checkpoint 没有保留）；所有规模都沿用这个学习率，不再重新选择。

dev 上的 SFT loss 和 OPD 反向 KL 只用来监控训练，不参与选择。

**正式训练（2026-11-24）**：两种方法都按上面的设置从头训练 200 步到 8k，一次跑完，没有中断；每 25 步的完整 checkpoint 都在 Google Drive 上。与方案的唯一差异是训练和生成的长度上限从 2048 提高到 4096（训练集有一个 2307 token 的 prompt，test 最长 1968 token）。结果在 `results/training/{sft,opd}_formal_v1/`，参照系统在 `results/training/test_references_v1/`，见[训练报告](../results/training/formal_v1_report.md)。

**OPD 选择结果（2026-11-23）**：`beta=0.5`，学习率 2e-6。两个 beta 各扫了三个学习率，组内都是 2e-6 胜出，组间对决 `beta=0.5` 胜率 0.62（95% 区间 0.56–0.68）。实际每步用了 40 个 prompt × 4 次采样；选定 run 的 1k checkpoint 没有保留，正式训练从头训练。详见[选择报告](../results/training/opd_lr_sweep_v1/report.md)。

**SFT 选择结果（2026-11-24）**：学习率 5e-6。三个候选在 dev 上分不出高下：平均胜率最高的是 1e-5（0.52），但它对第二名 5e-6 的区间含 50%，按规则取较小的 5e-6；三场比较的区间全部含 50%。每步同样用 40 条；各 run 的 checkpoint 没有保留，正式训练从头训练。详见[选择报告](../results/training/sft_lr_sweep_v1/report.md)。

**checkpoint 方案**：从 1k 续训到 8k 的过程中，在 1k、2k、4k、8k 四处保存权重。这四个 checkpoint 就是数据规模曲线上的四个点，全部在 test 上评测，不需要另外挑选 checkpoint。数据只过一遍，warmup 之后学习率恒定，因此每个 checkpoint 与"只用前 N 个商品训练"得到的结果相同。

## 6. 评测设计

### 6.1 评委

主评委用 DeepSeek，采用 pairwise-v0.2 协议：只看广告文本，AB 和 BA 两个顺序各评一次（选择依据见[四评委对比](../results/pairwise/comparison/report.md)）。不拿 397B 教师当参照，因为学生对它的胜率太低，会出现地板效应。

### 6.2 两层评测（test 集）

共 8 个 checkpoint：2 种方法 × 4 个规模。

| 层 | 方式 | 回答的问题 |
|---|---|---|
| ① 主结论 | 每个规模上，OPD 直接对比 SFT | 同规模下哪种方法更好 |
| ② 总排名 | Bradley–Terry 拟合：8 个主模型加 3 个参照（训练前的学生、397B 教师、GLM），稀疏设计 | 两种方法的分数怎样随数据规模变化 |

BT 拟合时，同一对的两个顺序取平均：两次都赢记 1，结论相反记 0.5，两次都输记 0。置信区间按商品做 bootstrap。拟合完要检查预测胜率是否与实际胜率吻合。

dev 上的学习率选择见第 5 节。

### 6.3 其他维度

- **护栏指标**：长度分布、超过 35 词的比例、照抄标题的比例、开头多样性、教师给出的整句 logprob。这些只作为描述性结果报告，不参与选择。不用"每 token 平均 logprob"作为质量指标。
- **事实准确性**：用单条 rubric 评测。主评委不检查编造内容。
- **人工盲评**：在 test 集的 8k checkpoint 输出中抽约 100 个商品，标注时隐藏模型身份。
- **案例分析**：对代表性样本，用 397B 逐 token 打分，找出改进和退化的来源。

### 6.4 下结论的规则（事先定好）

只有当 OPD 与 SFT 的差距超出 test 集 bootstrap 区间时，才能下"OPD 更好"或"OPD 更差"的结论，否则写成"没有证据表明两者有差别"。

两种方法都只训练了 1 个种子，这个区间只反映商品抽样的波动，不反映重新训练带来的波动。结论一律写成"在单种子下……"，并在差距较小时说明它可能来自训练随机性。

## 7. 局限

- 结论只适用于这个教师、这个评委和这个任务。
- 数据规模曲线反映的是"单遍训练过程中各个 checkpoint 的表现"，不是"每个规模各自训练到收敛的表现"。
- 两种方法都只跑了 1 个种子，没有评估训练随机性；test 区间只反映商品抽样的波动。
