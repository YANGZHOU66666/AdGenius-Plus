# SFT 与 OPD 的 test 评测（v1）

本文报告 SFT 与 OPD 两种方法训练的 0.8B 学生在 1,000 件 test 商品上的最终评测：广告质量（pairwise + Bradley–Terry）和事实准确性（rubric）。实验方案见 [SFT 与 OPD 实验方案](sft_opd_experiment_plan.md)，训练过程见[训练报告](../results/training/formal_v1_report.md)。状态截至 **2026-11-24**。

## 1. 结论

两项评测给出的方向相反：**SFT 写出的广告更受评委青睐，OPD 写出的广告与商品资料冲突更少。**

| 规模 | 广告质量：OPD 对 SFT 的胜率 [95% 区间] | 事实准确性：冲突率差 OPD − SFT [95% 区间] |
|---|---|---|
| 1k | 0.486 [0.46, 0.51]：没有证据表明两者有差别 | −3.7 个百分点 [−5.9, −1.5]：OPD 更少 |
| 2k | 0.467 [0.44, 0.49]：SFT 更好 | −3.0 [−5.2, −0.8]：OPD 更少 |
| 4k | 0.493 [0.47, 0.52]：没有证据表明两者有差别 | −1.7 [−3.7, +0.3]：没有证据表明两者有差别 |
| 8k | 0.446 [0.42, 0.47]：SFT 更好 | −1.9 [−3.8, 0.0]：在边界上，区间上端正好是 0 |

- **广告质量：** 在单种子下，OPD 在任何规模上都没有胜过 SFT，2k 和 8k 上 SFT 显著更好。方案中"OPD 在商品少时更省数据"的假设没有得到支持：1k 上两者没有差别。
- **事实准确性：** 在单种子下，OPD 在四个规模上的冲突率都低于 SFT，其中 1k、2k 的差距显著，8k 在边界上。
- **训练本身效果明显：** 两种方法训练 1k 后，对训练前学生的胜率约为 0.88，冲突率从 17.9% 降到 7.7%–11.4%。数据越多，两项都越好，但提升逐渐变慢。离 397B 老师仍有差距：老师对 SFT 8k 的胜率为 0.67，冲突率为 2.8%。

判定规则按方案第 6.4 节事先确定：区间不包含"没有差别"（胜率 0.5、冲突率差 0）才下结论。两种方法都只训练了 1 个种子，区间只反映商品抽样的波动，不反映重新训练带来的波动。2k 和 8k 上 3 到 5 个百分点的胜率差，以及 2 到 4 个百分点的冲突率差，都有可能来自训练随机性。

## 2. 评测设置

**系统（10 个）**：每个系统在 1,000 件 test 商品上各生成 1 条广告，均为 GenerationResult v1.1。

| 系统 | 说明 | 截断 | 失败 |
|---|---|---:|---:|
| `base` | 训练前的 Qwen3.5-0.8B | 21 | 0 |
| `sft_1k` … `sft_8k` | SFT（学习率 5e-6）在 1k/2k/4k/8k 商品处的 checkpoint | 0 | 0 |
| `opd_1k` … `opd_8k` | OPD（`beta=0.5`，学习率 2e-6）在 1k/2k/4k/8k 处的 checkpoint | 1k、2k 各 1；4k、8k 为 0 | 0 |
| `teacher_397b` | Qwen3.5-397B 老师 | 0 | 0 |

截断的广告保留原文，照常参与评测。生成失败按"判负"处理，但本次没有失败。

**评委**：两项评测都用 DeepSeek（`deepseek-flash`）。它是 pairwise 和 rubric 校准中一致率最高的评委，选择依据分别见[四评委对比](../results/pairwise/comparison/report.md)和 [rubric 人机一致率报告](rubric_judge_agreement.md)。DeepSeek 与学生、老师不属于同一个模型家族。

**设计先于结果**：比较设计（[test_sft_opd_v1.toml](../configs/eval/bt/test_sft_opd_v1.toml)）在任何 test 评委判断之前提交（`e1c2057`）。本次评测没有回头修改设计、规则或评委配置。

## 3. 广告质量：pairwise + Bradley–Terry

### 3.1 方法

- **协议**：`pairwise-v0.2`。评委只看两条广告的文字，不看商品资料，判断哪条在信息流中传播效果更好；AB、BA 两个顺序各判一次。
- **比较设计**：16 组对比，每组 1,000 个商品，共 16,000 对、32,000 次评委调用。各组如下：

  | 类别 | 对比 | 组数 |
  |---|---|---:|
  | 主结论 | OPD 对 SFT，1k / 2k / 4k / 8k | 4 |
  | 规模链 | SFT 1k–2k、2k–4k、4k–8k；OPD 同样三组 | 6 |
  | 起点 | `base` 对 SFT 1k、OPD 1k、SFT 8k、OPD 8k | 4 |
  | 参照 | 老师对 SFT 8k、老师对 OPD 8k | 2 |

- **记分**：每对的两个顺序取平均。两次都赢记 1，两次结论相反记 0.5（算作平），两次都输记 0。
- **Bradley–Terry 拟合**：以 `base` 为 0 分，分差 1 对应 73% 的预期胜率。每组加 0.5 个虚拟平局；按商品 bootstrap 2,000 次。链路说明见 [Bradley–Terry 评测链路](bradley_terry_eval.md)。

**评委运行情况**：32,000 次调用全部成功，没有失败或重试。两个顺序结论一致的占 73.7%；这些系统水平接近，平局本来就多。首位选择率为 49.5%，评委没有偏向先看到的广告。

### 3.2 Bradley–Terry 分数

| `teacher_397b` | 3.53 | [3.38, 3.70] |

| `sft_4k` | 2.53 | [2.39, 2.67] |
| `sft_2k` | 2.46 | [2.33, 2.62] |
| `opd_4k` | 2.46 | [2.32, 2.61] |
| `opd_2k` | 2.35 | [2.22, 2.49] |

| `opd_1k` | 1.94 | [1.80, 2.08] |

**吻合检查**：16 组对比的 BT 预测胜率全部落在观察区间内（cycle rank 7）。"每个系统一个分数"能够概括这些比较。

## 4. 事实准确性：rubric

### 4.1 方法

- **协议**：`rubric-v0.2` 的 `factual_support`（规则见 [rubric v0.2](individual_rubric_v0.2.md)）。评委看到与生成时相同的商品资料和一条广告，判断广告是否与资料冲突，判为冲突时要引用两边的原文。
- **规模**：10 个系统的 10,000 条广告在同一次运行中判完，评委、商品集合都相同。10,000 次调用全部一次成功。
- **区间**：冲突率和两两差都按商品 bootstrap。每个系统在每件商品上只有一条广告，结果非 0 即 1，所以 bootstrap 分布可以精确算出，不用抽样（`rubric_metrics.py`，`metrics.json` 里记为 `"method": "exact"`）。早先版本用 10,000 次抽样，8k 的差值区间因抽样误差得到 [−3.8, −0.1]，精确值是 [−3.8, 0.0]。

### 4.2 各系统的冲突率

| 系统 | 判为冲突 | 冲突率 [95% 区间] |
|---|---:|---|
| `base` | 179 | 17.9% [15.6, 20.3] |
| `sft_1k` | 114 | 11.4% [9.5, 13.4] |
| `sft_2k` | 109 | 10.9% [9.0, 12.9] |
| `sft_4k` | 92 | 9.2% [7.4, 11.0] |
| `sft_8k` | 80 | 8.0% [6.4, 9.7] |
| `opd_1k` | 77 | 7.7% [6.1, 9.4] |
| `opd_2k` | 79 | 7.9% [6.3, 9.6] |
| `opd_4k` | 75 | 7.5% [5.9, 9.2] |
| `opd_8k` | 61 | 6.1% [4.7, 7.6] |
| `teacher_397b` | 28 | 2.8% [1.8, 3.9] |

判为冲突、却没有引用资料原文的共 14 条，按规则这些不应算作冲突，但上表仍算作冲突。它们分散在各系统中，每个系统 0 到 5 条。如果把它们改算为不冲突，1k、2k 的差值仍然显著，8k 变为 −1.7 [−3.6, +0.2]，不再显著。

### 4.3 关键差值

同一批商品上的配对差（前者减后者），单位为百分点：

| 比较 | 冲突率差 [95% 区间] |
|---|---|
| OPD 1k − SFT 1k | −3.7 [−5.9, −1.5] |
| OPD 2k − SFT 2k | −3.0 [−5.2, −0.8] |
| OPD 4k − SFT 4k | −1.7 [−3.7, +0.3] |
| OPD 8k − SFT 8k | −1.9 [−3.8, 0.0] |
| SFT 1k − SFT 8k | +3.4 [+1.1, +5.7] |
| OPD 1k − OPD 8k | +1.6 [−0.4, +3.6] |
| `base` − SFT 8k | +9.9 [+7.2, +12.6] |
| `base` − OPD 8k | +11.8 [+9.2, +14.5] |
| SFT 8k − 老师 | +5.2 [+3.4, +7.1] |
| OPD 8k − 老师 | +3.3 [+1.7, +5.0] |

- OPD 在 1k 时冲突率就已经降到约 7.7%，之后变化不大：1k 到 8k 的差没有显著性。
- SFT 的冲突率随数据量逐渐下降，1k 到 8k 下降了 3.4 个百分点。即使到了 8k，SFT 的冲突率（8.0%）仍与 OPD 1k（7.7%）相当。
- 相邻两档之间的冲突率差，两种方法都不显著。

**解读限制**：这些是评委判出的冲突率，不是人工标签。在 gold 的 130 条人工样本上，这个评委只抓到 18 条人工冲突中的 12 条（[rubric 人机一致率报告](rubric_judge_agreement.md)），所以绝对冲突率偏低，适合比较系统之间的高低。评委主要在 qwen_local 那类错误上验证过。

## 5. 两项结果之间的关系

pairwise 评委只看广告文字、看不到商品资料，因此无法发现编造或与资料冲突的内容。一条写得更具体、更吸引人但与资料冲突的广告，可能在 pairwise 中获胜，而在 rubric 中被判为冲突。这一点与观察到的现象一致：SFT 胜率更高，同时冲突更多。训练笔记的冒烟测试中也记录过 SFT 编造信息的例子（[训练实验杂记](training_notes.md)）。

这是一种可能的解释，本报告没有验证它。要检验，可以看同一商品上 SFT 赢了 pairwise、却被 rubric 判为冲突的样本有多少、是什么类型。

## 6. 局限

- **单种子**：两种方法各只训练了 1 个种子，没有评估训练随机性。
- **单一评委**：两项评测都只用了 DeepSeek，没有第二个评委或人工盲评复核 test 上的结论。
- **评委的覆盖范围**：pairwise 评委不检查事实；rubric 评委会漏掉约三分之一的冲突，且主要在一类错误上验证过。
- **规模曲线**：曲线反映的是单遍训练过程中的 checkpoint，不是每个规模各自训练到收敛的结果。
- **适用范围**：结论只适用于这个老师、这两个评委和这个任务。
- **评委随机性**：即使 temperature 为 0，同一配对重判时约有 5% 的结论会变（仓库外的并发测试）。按商品 bootstrap 的区间已经包含了这部分波动。
